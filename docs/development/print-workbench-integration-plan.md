# 打印预览布局修复与通知、奖状合并计划

状态：已按用户后续指令实施；验证记录见 [通知真实素材复刻验证](notice-material-validation.md)。

补充约束（2026-10-04）：已按用户要求用真实通知素材做对照，结果见 [通知真实素材复刻验证](notice-material-validation.md)。首轮通用画布复刻未通过。本次增加独立的素材文档渲染，六组原始尺寸和普通场景 2 倍 PNG 均达到零像素差异，保存后的模板不调用原通知 Vue 组件。

## 一、已确认的问题

主布局 `MainPage.vue` 的 `.main-content` 固定为窗口可用高度并设置 `overflow: hidden`。批量报告、奖状卡片、考试分析三个页面使用 `height: auto; min-height: 100%`，内容随设置和预览持续增高，却没有承担滚动的受限高度容器，超出主内容区的部分被裁掉。

批量报告虽然为预览配置了 `overflow: auto`，但预览自身没有受限高度，所以不会产生有效的纵向滚动。奖状的设置面板、画布和导出按钮也都随内容向下延伸。考试分析整张 A4 预览同样超过视口。

此前验证了导出文件和分页，未把“鼠标滚动到预览末尾、操作最后一个设置项、在矮窗口下使用”作为实际交互验收，因此遗漏了这些问题。名单打印采用同样结构，纳入本次排查和修复。

## 二、目标布局

所有相关制作页面采用固定高度工作台：页面标题与主要操作常驻，设置面板和预览区分别在剩余空间内滚动。工作台使用完整的高度约束与 `min-height: 0`、`min-width: 0`；每个区域明确自己的滚动责任。

| 页面           | 设置区域                                                   | 预览区域                                       | 常驻操作                                    |
| -------------- | ---------------------------------------------------------- | ---------------------------------------------- | ------------------------------------------- |
| 批量学习报告   | 左侧：名单、成绩范围、正文编辑；独立滚动                   | 右侧：报告；默认适应宽度，长报告纵向滚动       | 切换学生、缩放、生成/停止、ZIP/PDF、进度    |
| 奖状与表扬卡   | 左侧：名单 / 版式 / 内容 / 图层选项卡；独立滚动 | 右侧：画布；默认整页适应，可放大查看和编辑     | 保存模板、切换学生、缩放、PNG/ZIP/PDF、停止 |
| 考试分析打印稿 | 左侧：测评、是否附明细；独立滚动                             | 占据其余空间；默认适应宽度，可完整滚动查看每页 | 页码、缩放、下载 PDF                        |
| 名单打印       | 左侧模板设置独立滚动                                       | 右侧纸张预览独立滚动                           | 页码、缩放、下载 PDF                        |

预览提供“适应宽度 / 整页适应 / 100%”及缩放控制。放大后可横向与纵向滚动，容器变小时自动重新计算适应比例。缩放后的占位尺寸与实际显示一致，确保滚动到最后一行。

批量报告将原来顶部占用两大块空间的名单和配置移到侧栏，保留简短人数与进度摘要。奖状在较窄 PC 窗口中把两侧设置合并为一个带选项卡的侧栏，给画布留足宽度。默认针对桌面使用，不另做手机录入流程。

导出按钮位于工作台自己的固定操作区，正常参与布局，始终处于版权栏上方。失败明细在可滚动面板或展开区域展示，避免将预览压成零高度。

预览缩放只改变屏幕显示，不改变原始纸张尺寸、PDF 分页或 PNG 分辨率。奖状拖动与缩放图层时，按实际显示尺寸换算毫米坐标。

## 三、成绩通知与奖状的合并方案

工具中心合并为一个“通知与奖状”入口，共用一套制作工作台。首版包含四种模板类型：成绩通知、奖状、表扬卡、自定义模板。

统一操作流程：选择模板 → 选择或导入名单 → 填写/映射内容 → 逐人预览 → 批量导出。根据模板类型显示必要的设置。

| 能力         | 合并后的行为                                                                              |
| ------------ | ----------------------------------------------------------------------------------------- |
| 成绩通知     | 继续支持科目配置、分数/等级、等级规则、人工及 AI 评语、手写字体和原有通知版式             |
| 奖状和表扬卡 | 支持姓名、称号、正文、学校、落款、日期等变量与素材图层                                    |
| 自定义模板   | 上传背景，添加文字/图片及结构化成绩、评语内容块，保存后复用                               |
| 名单         | 共用系统名单/Excel 来源与学生切换；Excel 同名学生保留独立行身份                           |
| 预览         | 共用滚动、缩放、分页/学生切换；各模板使用相应内容渲染器                                   |
| 输出         | 共用单张 PNG、批量 ZIP、合并 PDF 的入口和进度反馈；小卡支持四联 PDF，成绩通知保留复制图片 |

成绩表作为结构化内容块：读取科目与当前学生成绩，保留缺失值、等级规则和有效分数判断；科目较多时采用已有紧凑排版并提示溢出。评语作为独立内容块，支持换行、文本框尺寸和手写字体。通用文字层仍使用 `{{字段名}}` 替换，不负责重新计算等级或生成成绩结论。

原成绩通知模板通过现有组件渲染以保留原版式；自定义成绩模板通过结构化内容块接入通用编辑器。渲染器共用工作台及输出协议，无需在界面中展示内部实现区别。

通用编辑器必须先以现有通知为完整素材样例，补齐字体、字距、行距、描边、阴影、文本布局和成绩/评语内容块，再完成可编辑模板复刻。动态内容独立填入，更换学生仍能复用。现有通知渲染器的适配只作为内置模板保真方案，不能据此宣称上传素材制作同款通知的能力完成。

切换模板类型时，已有名单可复用；需要成绩的模板要求补齐成绩列映射。未保存的模板编辑、正在生成的评语及导出任务必须在切换前处理，避免丢失工作。

### 数据与兼容

- 成绩通知数据继续跟随当前班级/学期，沿用 `score_notice` 记录及工作区快照。
- 可复用模板继续全局共用，保存于 `tools`，素材使用内嵌快照；不把具体学生名单写入模板。
- 现有成绩通知记录、已保存奖状模板和完整备份都能继续读取。新增结构化图层字段按版本/缺省值兼容，不强制重建现有数据。
- 两个旧地址 `/tools/score-notice`、`/tools/cards` 导向统一工作台对应的模板类型；工具中心只展示一个合并入口。
- 批量学习报告和考试分析各自保留入口，复用预览基础组件。
- 不增加依赖，不安装或更新包，不引入备份字体 `SourceHanSerifSC-Regular.otf`。

## 四、代码拆分

建议的模块边界如下，文件名称可按现有项目约定微调：

| 模块                       | 职责                                                 |
| -------------------------- | ---------------------------------------------------- |
| `PrintWorkbenchLayout.vue` | 固定标题/操作区、受限高度主体、侧栏布局与窄窗口适配  |
| `PrintPreviewViewport.vue` | 实际可滚动的预览视口、缩放占位和预览控制栏           |
| `usePrintPreviewScale.ts`  | 监听容器尺寸、适应宽度/整页、缩放状态与坐标换算      |
| `NoticeAwardPage.vue`      | 组合统一入口、模板类型与制作区域                     |
| `NoticeContentPanel.vue`   | 科目、成绩模式、等级规则、评语设置，复用现有子组件   |
| 现有卡片设置/图层面板      | 纸张、素材、变量和图层编辑                           |
| 数据适配与导出组合函数     | 学生身份映射、冻结批次、渲染器调度、取消、错误及输出 |

页面只负责组合，不把名单解析、内容渲染、导出队列和所有设置写进一个大文件。新增工具函数、组合式函数及坐标/身份/兼容规则补充中文注释。

## 五、实施顺序与阶段交付

1. **先修复预览布局。** 提取工作台与预览视口，调整批量报告、奖状、考试分析与名单打印。完成实际滚动和缩放验收，交付可独立验证的修复。
2. **合并制作流程。** 增加“通知与奖状”工作台，接入原通知模板及奖状/表扬卡模板，共用名单选择、学生预览和导出入口；处理旧路由与保存数据兼容。
3. **接入通用成绩模板。** 先修复原通知紧凑/密集版选择器导致的裁切和隐藏，建立完整基准。补齐通用文字样式、成绩与评语内容块，以真实素材制作可编辑的同款通知并通过图片对照；完善溢出提示、手写字体、批量输出和旧备份恢复。
4. **完成回归与交付。** 检查真实鼠标滚动、图层编辑、导出文件及数据兼容；运行类型检查、Lint、相关测试与生产构建，更新使用文档。

审核通过后按以上四步实施；本计划不包含部署或发布。

## 六、验收标准

### 布局和操作

- 在 1366 × 768、1920 × 1080、1024 × 768 的 PC 窗口及浏览器 125% 缩放下检查。
- 报告长正文、奖状竖版纸张/多图层、考试分析多页明细均能用鼠标滚动到最下方；侧栏最后一个设置项可操作。
- 主要导出、停止按钮始终可见，预览和设置不被版权栏遮挡。
- 改变窗口尺寸或展开配置后，预览仍有可用高度；较窄窗口不存在横向挤出屏幕的操作按钮。
- 适应宽度、整页、100% 和手动缩放都有效；放大后能滚动到四边，奖状图层拖动/缩放与最终输出位置一致。

### 功能与数据

- 真实通知素材复刻是合并方案的硬性验收：同一浏览器、字体、尺寸和导出倍率下，对照原始 PNG，正常原通知内置模板保持零像素差异，通用素材模板也以零像素差异为目标；任何差异逐项定位，不能只以“基本相似”交付。
- 所有基准图先检查完整性；现有 8 科目裁切和 12 科目隐藏应修复后建立新基准。不能把整张已填入学生数据的原图作为模板，也不能将两张同样裁切/空白的图片算为通过。
- 原通知模板的科目、等级转换、评语和手写字体继续可用；原成绩通知数据、旧模板与备份可恢复。
- 系统名单、Excel 自定义字段、重复姓名、空姓名行、真实 0 分和缺失成绩分别验证。
- 单张 PNG、ZIP、合并 PDF、四联 PDF 逐一实际下载，检查非空内容、姓名、页数、完整正文及纸张尺寸。
- 长内容不能静默裁切；错误学生可定位，停止后的已完成结果可处理；导出或评语生成期间切换受到保护。
- 新增测试覆盖有风险的布局行为、内容块、身份映射、旧模板兼容与备份恢复；浏览器测试实际改变滚动位置并检查末尾可见，不能只依赖截图或导出成功提示。

## 实施结果与实际边界

- 批量学习报告、通知与奖状、名单打印、考试分析共用 `PrintPreviewViewport`；设置、预览、图层列表、评语筛选与操作栏均使用 Element Plus 滚动组件。长文本自动增高，避免编辑框额外出现原生滚动条。
- 五个制作页面使用 60 人虚构班级，在 1024×768、1366×768、1920×1080 中验证预览滚动到底部、横向滚动和导出按钮位置。
- 通知与奖状合并为单一入口，旧链接保留重定向。原通知保留科目规则、AI/人工评语与自定义手写字体；增加 PNG、PDF，保留复制和 ZIP。通知批次冻结数据，可停止后下载部分结果，同名文件带连续编号。
- 奖状制作采用四个侧栏选项卡；支持图片替换、文字字体/行距/字距/描边/阴影、图层拖动、模板保存与读取。连续编辑合并为串行预览任务。
- 从现有通知创建素材模板时，以已导入通知的当前科目和版式生成纯素材文档，文字替换为变量、图片与字体内嵌去重；自动选择通知名单，使每名学生使用自己的成绩与评语。模板存储不包含学生姓名、分数或评语正文，完整备份保留素材文档。
- 转换后的素材模板保持捕获时的科目数量和分组结构。改变科目数量应重新转换；新增图片和文字可调整叠放顺序，原素材分组保留原顺序。原生通知继续根据科目数自动选择普通/紧凑/密集版式。上传图片不会自动识别其中的文字或生成排版，应添加变量文字层。
- 独立实验像素验收为零差异；正式页面另有 482 个装饰边缘像素相差单通道 1/255，无内容或位置变化，已单独记录。未宣称跨系统字体逐像素一致。

最终验收：另覆盖 1280×600 矮窗口与 1093×614 逻辑视口、停止并下载通知部分结果、素材替换保存及缩放后毫米坐标拖动。全量 747 项测试与最终相关 23 项回归通过，类型检查、ESLint、生产构建通过。
