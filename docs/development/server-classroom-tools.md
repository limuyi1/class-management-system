# 服务器座位表与值日表

## 数据归属与入口

登录后进入班级学期，打开“座位表与值日表”。每个方案只属于一个账号、班级和学期；进入新学期不会自动复制这些安排。需要另行创建。超级 VIP 管理员使用顶部账号选择器后，可在明确提示的目标账号范围内操作；身份始终保持为实际管理员。

schema v5 的 `classroom_tools` 保存独立方案、版本、内容、创建/更新时间及软删除时间。方案删除保留原内容，普通列表不显示。删除临时 Excel 名单中的学生仅修改该方案，不改变系统名单；实际保存时仍需显式点击“保存方案”。目前没有回收站恢复界面。

## 当前已接入的功能

- 创建、复制、命名、编辑、保存和删除方案，备注说明随方案保存。
- 系统名单只使用当前学期未禁用、未转出的学生；临时 Excel 名单沿用姓名列解析及名单增删组件，按 ID 区分同名学生。
- 座位表：1～20 行/列、座位选择、随机排座、补充空座、四方向轮换与固定学生、列间过道、第一列方向、讲台方向、雅座、职务配置。
- 值日表：每日/每周模式、区域与岗位编辑、区域大组长、增加周表组、岗位学生多选、自动分配。
- 原有打印版式与 Excel、PNG、PDF 导出组件复用；文件来自已保存服务器方案。先保存再导出，草稿不会冒充已保存结果。

服务端接入界面采用独立编辑器，不读取旧 Pinia 全局名单或 Dexie 方案。本轮已补齐以下交互：座位拖拽交换/回收、值日矩阵拖拽换岗/回收、卡片数量与复制、多个时段组长、岗位拖拽排序、周表组排序/删除、自动分配容量与预览。旧版全屏、完整右键菜单和区域排序等细节仍待逐项验收。手机设计仍在二阶段。

## 保存、冲突与名单变化

客户端每次提交携带方案版本和幂等键；内容相同的网络重试沿用原键。新建版本为 0，成功后服务端生成时间戳并提升版本。其他设备已修改或删除时返回 409，前端保留原草稿与原版本，不自动强行覆盖。

修改方案期间切换账号、学期或业务页签会确认是否放弃草稿；提交和导出过程中阻止切换。关闭管理员代管资格时立即清理草稿及导出状态；服务端每个请求独立重查权限。

系统学生禁用、转出或删除后，旧方案原始内容保留。在编辑副本中自动移除无效引用，产生未保存草稿；确认保存后才更新服务器。服务端拒绝包含无效学生的新安排。临时 Excel 名单与系统名单不自动按同名合并。

## 导出保护

打开打印预览时重新读取服务器快照，并保存学生 ID 对应的姓名。当导出开始，以及 PNG/PDF 生成完毕准备下载时，再验证当前权限、方案版本、名单和账号学期。发生撤权、名单变动、方案变更或离开页面时终止下载，避免旧范围文件晚到。

包含无效学生引用的系统方案必须先编辑、保存，再导出。Excel 下载为同步生成，下载前校验一次；PNG/PDF 异步生成后也再次校验。旧本地模式不传鉴权回调，继续使用原有导出行为。打印组件的纸张、缩放和格式设置属于本次弹窗状态，本轮没有新增账号级全局设置。

## API 与实现位置

所有路径前缀为 `/api/v1`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/workspaces/:id/tools` | 读取方案和本期名单 |
| PUT | `/workspaces/:id/tools/:toolId` | 新建/更新一个方案，含 expectedVersion、kind、content |
| DELETE | `/workspaces/:id/tools/:toolId` | 按 version 软删除 |

写请求要求 `Idempotency-Key`；代管范围通过已有 `X-Managed-Account-Id` 处理。JSON 白名单拒绝 owner、role、未知字段；关系校验拒绝重复座位、重复学生、无效岗位/周期/职务以及不属于本期的学生引用。读写审计记录实际 actor 和 owner。

- 迁移：`server/migrations/005-classroom-tools.sql`
- 类型：`packages/shared/src/ClassroomTools.d.ts`
- 服务、关系验证及路由分别拆在 `server/src/services/classroomTools.ts`、`classroomToolValidation.ts` 和 `server/src/routes/classroomTools.ts`、`classroomToolSchemas.ts`。
- 前端入口：`ui/src/views/workspace-api/ClassroomToolsPanel.vue`；座位、值日、目录分别拆分组件，草稿与导出分别拆分 hooks。

## 本轮验证范围

仅运行相关基本测试、必要类型检查和改动文件 Lint。前端相关 7 个文件共 20 项、后端相关 2 个文件共 4 项通过。后端使用内存 SQLite 与 Fastify inject，不启动监听端口；前端验证草稿冲突/重试、失效学生清理、导出撤权/销毁/改名，以及复用的排座轮换、自动值日和 Excel/导出组件。没有执行全量回归或前端完整生产构建，也没有实际打开浏览器验收纸张和打印效果。

真实开发数据库由用户下一次运行启动脚本时执行增量迁移，本轮没有初始化管理员、迁移旧浏览器数据、停止占用端口的进程或启动开发服务。

## 高级交互补齐（2026-10-07）

复用原来的座位画布、待选学生面板和值日矩阵，不引入旧全局业务 Store。拖入已占用座位会交换两人，待选学生拖入则让原学生回到待选区。普通座位与启用的雅座可以互换；未知学生不可拖入。

值日卡片每人 1～100 张，总数最多 5000。复制和数量编辑不删除已安排卡片；最小数量为已安排次数。换岗、移回待选区以及删除周表组前先固定历史推导的卡片数量，避免复制卡片丢失。清理已删除岗位/周表组的容量和不在岗的时段组长。

同一区域、时段允许多个组长；服务端拒绝重复的同一学生组长记录，也拒绝没有在该区域安排岗位的时段组长。区域大组长独立设置，不受该条件影响。岗位排序及周表组排序保持 ID，不改变分配关系。

自动分配可设置每个岗位格 0～100 人容量，选择保留既有安排或重新分配。生成预览不改变当前安排，确认后仅写入草稿，仍需保存到服务器。名单、卡片、容量、安排或保留选项改变后旧预览失效；确认过程中离开组件不应用旧预览。

本次新增/复验仅覆盖相关交互和服务端关系校验，不重复全量回归；没有实际浏览器拖拽、打印或移动端验收。
