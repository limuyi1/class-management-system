# Node.js + SQLite 前后端分离改造方案

日期：2026-10-07。版本：第四版（确认移除账号级备份/恢复/清空入口、账号软删除与启动自动释放端口）。状态：已审核，开始分阶段实施；实际完成情况见 [实施记录](./node-sqlite-implementation.md)。

改造分支：`node-sqlite-migration`，从当前本地 `V5.0` 的 `6dc7bf6` 创建。用户已批准开始在此分支分阶段实现，原分支保留本地版。安装依赖遵循 AGENTS.md 的明确授权要求，上线和迁移实际使用数据另行确认。

## 1. 目标与范围

将当前浏览器本地应用改为服务器统一存储的 Web 应用，支持少量用户登录、同一用户跨设备访问，保留现有班级、学期、成绩、评语、历史参照、排表及打印功能。

第一版采用以下产品边界，作为本次审核的默认建议：

- 管理员创建、编辑、重置密码、禁用/启用、删除普通账号；手机号作为用户名，创建时生成默认昵称。普通账号可修改自己的昵称和密码。管理员账号禁止删除、禁用和降级。
- 各账号拥有独立数据空间；同一账号的班级、学期和业务数据跨设备共享。
- 暂不支持普通账号之间共同编辑班级。管理员启用“超级 VIP（账号代管）”后，在顶部选择目标账号，切换其班级、学期及业务数据，复用现有页面进行查询、新增、编辑和删除；登录身份始终是管理员。
- 在线编辑、在线保存；断网显示保存失败并保留当前页面草稿，重新联网后由用户重试。首次加载失败不能以空默认值覆盖服务器数据。
- 第一阶段完成桌面 Web；第二阶段建设手机常用工具界面，微信小程序作为后续独立客户端接入。第一阶段即统一认证和 API，避免再设计一套账号体系。
- 第一版使用单台服务器、单个 API 服务实例，不实现多服务器部署、微服务、Redis、消息队列、实时协同或完整离线同步。
- 服务器版移除本人及代管账号的完整业务备份导出、恢复和一键清空入口，由运维统一备份数据库与附件。保留成绩 Excel/PDF 等业务导出，以及上线前的旧本地版数据一次性迁移。

最终交付覆盖现有业务功能。中间阶段仅用于开发验收，在其他模块尚未迁移时不作为完整可用的服务器版本发布。

## 2. 技术选择

| 层级     | 方案                                   | 说明                                                             |
| -------- | -------------------------------------- | ---------------------------------------------------------------- |
| 前端     | 现有 Vue 3 + TypeScript + Vite         | 保留 Element Plus、VxeTable、Pinia、hash 路由                    |
| 后端     | Node.js + TypeScript + Fastify         | 使用实施时仍受支持的 Node.js LTS，锁定兼容依赖版本               |
| 数据库   | SQLite                                 | 本地持久化磁盘，单个服务实例负责业务写入                         |
| 数据访问 | Drizzle ORM + better-sqlite3           | 提交 SQL 迁移文件，生产环境执行已审核迁移                        |
| API      | REST + JSON Schema + OpenAPI           | 后端进行运行时校验，响应使用明确 DTO                             |
| 登录     | 短期 Access Token + 轮换 Refresh Token | Web 与未来移动端共用认证服务；令牌可撤销，服务端保留设备登录记录 |
| 文件     | 本地附件目录 + SQLite 元信息           | 经鉴权接口下载，使用服务器生成的存储名称                         |
| 部署     | 反向代理 + 一个 Node.js 服务           | 前端静态文件与 `/api/v1` 同域，生产使用 HTTPS                    |

SQLite 启用 `foreign_keys=ON`、WAL，初始建议 `busy_timeout=1000` 毫秒、`synchronous=FULL`，在验收中根据写入延迟调整。WAL 允许读写并行，但仍只有一个写事务；不要将数据库放在 NFS 等网络共享目录。

better-sqlite3 的调用是同步的，锁等待及大查询会占用所在线程。第一版保持查询有界、事务短小，批量导入限制大小；大型转换放在事务外。若验收发现明显阻塞，增加专用数据库 Worker，而不是单纯放大等待时间。数据库事务内禁止 AI 请求、文件上传或其他网络等待。

暂不实现 SQLite / PostgreSQL 双数据库兼容。保留清晰的 Repository 边界，但未来更换数据库仍需 schema 调整、数据搬迁和验证。

## 3. 项目结构与职责

采用 pnpm workspace，将前端完整移入 `ui/`，后端放在 `server/`，根目录只承担统一命令、工作区配置和说明文档：

```text
package.json                # 私有根包，统一 dev/build/test/lint 命令
pnpm-workspace.yaml
pnpm-lock.yaml              # 全仓使用一份锁文件
ui/
  package.json
  src/                      # 现有 Vue 源码
    api/                    # 请求、认证、错误处理
    repositories/           # 业务数据访问接口及 API 实现
    adapters/               # DTO 到表格/Store 的转换
  tests/                    # 现有前端测试
  public/
  index.html
  vite.config.ts            # 与 tsconfig、环境示例一起迁移
server/
  package.json
  src/
    routes/                 # HTTP 接口与 schema
    services/               # 业务规则、权限、事务
    repositories/           # 数据库读写
    db/                     # Drizzle schema 与连接
    auth/                   # 登录、令牌、账号管理
    policies/               # 普通访问、账号管理、账号代管访问策略
    migrations/             # 旧版业务数据转换服务
  migrations/               # 版本化 SQL 文件
  tests/
packages/shared/            # 独立包：DTO、错误码、接口契约
scripts/
  dev_launcher/             # Python 启动辅助模块
start.py                    # 一键启动入口
docs/                       # 架构、API、启动、部署、迁移、用户手册
```

根脚本使用 `pnpm --filter` 调用子工程；共享包使用 `workspace:*`。迁移时同步调整别名、测试路径、构建路径、环境读取、资源引用和 CI，前端输出为 `ui/dist/`，后端输出为 `server/dist/`。前后端可独立构建部署；不拆成多个仓库。数据库、上传文件、密钥和备份目录均在源码目录之外，不进入 Git。

业务调用链：页面 → Pinia action → 前端 Repository → API → 后端 Service → 数据库 Repository。

- Pinia 保存加载数据、编辑草稿及保存状态，不再以整个 Store 自动上传作为业务写入机制。
- 后端是权限、数据一致性和业务写入的权威；TypeScript 类型不能代替接口校验。
- 图表、打印预览和现有 Excel/PDF 导出优先复用前端实现。
- 后端实施影响数据一致性的校验；统计纯函数可逐步提取共享，防止重复实现不同口径。
- 不新增对备份字体 `SourceHanSerifSC-Regular.otf` 的运行时依赖。

## 4. 数据模型及归属

第一版使用账号级数据隔离。请求层统一传递当前代管账号，后端集中解析真实操作者 actor 与数据归属 owner：普通用户的 owner 只能为本人；管理员且已启用超级 VIP 时才允许指定目标账号。指定范围后，所有业务查询和写入仍须检查资源归属，不能因管理员身份跳过 owner 检查。权限矩阵见第 14 节。

| 表/数据                            | 归属与关键约束                                                                                                |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `users`                            | UUID、唯一规范化手机号、昵称、密码哈希、角色、状态、超级 VIP 标志、强制改密标志、authVersion、version         |
| `auth_sessions`、`auth_tokens`     | 设备登录、Access/Refresh Token 摘要、轮换族、到期、撤销与客户端类型；不存明文令牌                             |
| `captcha_challenges`、`audit_logs` | 短期验证码挑战/票据、管理员操作及账号代管查询/写入审计；记录 actor 与 owner，挑战到期清理，日志不含密码和令牌 |
| `classes`                          | ownerId、长期班级身份；改名保留往期名称                                                                       |
| `workspaces`                       | classId、termName、当期 className、默认满分、version；同班学期名唯一，同账号同学期班名唯一                    |
| `students`                         | ownerId、studentId；身份在同账号内跨期延续，不按姓名合并                                                      |
| `enrollments`                      | workspaceId、studentId、当期姓名、disabled、departed、version；工作区与学生组合唯一                           |
| `assessments`                      | workspaceId、原 prop、标题、顺序、disabled、可选满分、version；工作区与 prop 组合唯一                         |
| `scores`                           | workspaceId、studentId、assessmentId、可空分数、version；学生与测评唯一，保证测评与名单属于同一工作区         |
| `comments`、标签相关表             | 工作区内评语、标签分类、标签字典、学生标签；保持原先分类与值映射                                              |
| `workspace_references`             | 目标工作区与来源测评关系，限同账号；按现有规则引用本班其他学期，禁止悬空引用                                  |
| `workspace_documents`              | 通知单、座位表、值日表、学情缓存等，以带类型和版本的 JSON 分项存储                                            |
| `user_settings`                    | 用户级 AI 提示词、导出版式、工具设置和可同步的字体配置等                                                      |
| `paper_drafts`                     | 用户级版纸草稿；独立实体或带版本 JSON，沿用现有内容结构                                                       |
| `attachments`                      | ownerId、资源 ID、类型、大小、摘要、存储路径；下载校验归属                                                    |
| `mutation_receipts`、`import_jobs` | 幂等请求结果、导入状态、校验摘要及错误报告，按保留期限清理                                                    |

主键优先沿用现有 UUID。旧数据的 ID 保留为账号内业务 ID，可使用 ownerId + 原 ID 复合约束，避免不同账号导入同一备份时碰撞。外键及唯一约束负责最终一致性，Service 补充跨关系校验。

成绩不再作为学生表中的动态列存储。前端适配器按当前测评组装现有 `StudentDataType`，保留动态 prop，降低表格改造范围。`name` 是基础字段，不生成测评记录。

设备偏好（主题、界面字号、当前工作区、当前录入列）可以留在浏览器，按登录账号隔离；近期录入记录按账号和工作区保存。默认满分属于工作区。用户可同步的版式和字体资源属于账号，不再是全部账号共用的全局数据。

## 5. 必须保留的业务规则

- 学生以 ID 跨期关联；同名学生不能合并。姓名和在班状态保留各期版本。
- 未录入、缺考等缺失成绩保持空值，零分有效；不在迁移时凭空新增缺考状态或补零。
- 保留原始分、测评满分、启停状态和排序。默认满分修改继续遵循现有按学期回退语义。
- 本期统计不包含历史参照；连续趋势可以包含。历史排名按来源学期原名单计算。
- 历史参照不复制成绩到本期；被引用的学期或测评不能直接删除。
- 新学期保留学生 ID，可选择沿用测评和标签配置，清空本期成绩、评语及学生表现标签。
- 转班在单个数据库事务内完成：来源保留成绩，目标成绩和评语为空；第一版限同账号、同名学期。
- “删除学生”仅删除该期名单与相关业务引用，不删除往期身份和记录。
- 座位表、值日表沿用后按当前名单校对；独立 Excel 来源名单保持其独立性。

## 6. 工作区加载与跨设备保存

现有 `src/utils/workspaceUtil.ts` 使用当前 main 业务表与快照互换。服务器版每个工作区直接保存自身数据，切换不再修改服务器全局“当前班级”，也不覆盖其他工作区。

前端切换步骤：确认未保存草稿 → 等待当前工作区已提交写入完成 → 加载目标工作区 → 替换 Store 数据 → 清理选择和临时表单。旧请求响应必须同时校验 workspaceId 与加载代次，不能回填到新工作区。

单元格可以乐观显示，但每条待保存操作显式绑定工作区和记录版本；显示保存中、已保存、保存失败。失败保留草稿并允许重试，未确认提交的修改不能在离开页面时静默丢失。

写接口采用条件更新：`UPDATE ... WHERE version = expectedVersion`，成功递增版本；不匹配返回 `409 VERSION_CONFLICT` 并携带服务器最新值。同一新成绩并发创建通过唯一约束与“预期不存在”条件处理。批量录入任何一项冲突则整体回滚并返回冲突列表，不自动覆盖。

针对成绩批次、转班、新学期和导入，使用客户端生成的幂等键。后端将键、请求摘要、结果与业务修改一并记录，避免网络超时后重试产生重复操作；同键不同请求拒绝执行。

跨设备第一版通过进入页面、窗口重新获得焦点和手动刷新获取最新数据；存在未保存草稿时提示服务器有更新，禁止直接覆盖草稿。暂不承诺实时同步。

账号代管切换先于班级、学期切换：先处理原账号未保存内容和待提交操作，再清空原账号 Store 与选择状态，加载目标账号目录及工作区。所有请求、草稿、缓存和异步任务绑定 actor、owner、workspaceId 与加载代次；切换账号不能改变已发出操作的归属，也不能接受旧账号响应回填。具体界面和切换步骤见第 14.2 节。

## 7. API 草案

统一前缀 `/api/v1`，资源接口进行令牌、账号状态、权限和归属校验；列表设置数量上限，批量请求有大小上限。工作区初始加载可提供一个事务内读取的聚合接口，避免名单与测评处于不同版本。

| 接口                                                                          | 作用                                                            |
| ----------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `POST /auth/login`、`POST /auth/refresh`、`POST /auth/logout`、`GET /auth/me` | 登录、轮换续期、退出、当前用户                                  |
| `POST /auth/captcha/challenges`、`POST /auth/captcha/verify`                  | 滑块挑战与服务端校验                                            |
| `PATCH /me/profile`、`POST /me/password`                                      | 修改昵称、验证旧密码后修改密码                                  |
| `GET /me/devices`、`DELETE /me/devices/:id`                                   | 设备登录列表和主动下线                                          |
| `GET/POST /admin/users`、`PATCH/DELETE /admin/users/:id`                      | 普通账号管理，管理员保护由后端强制实施                          |
| `POST /admin/users/:id/reset-password`、`PATCH /admin/users/:id/status`       | 重置密码、禁用/启用                                             |
| `PATCH /admin/me/super-vip`                                                   | 管理员确认密码后启用/关闭自己的超级 VIP 权限                    |
| `GET /admin/managed-accounts`                                                 | 顶部账号选择器：返回允许代管的账号摘要，不返回密码或密钥        |
| `GET /workspaces`、`POST /workspaces`                                         | 目录、创建班级学期                                              |
| `GET /workspaces/:id/state`                                                   | 本期名单、测评、配置及版本，不返回所有附件内容                  |
| `GET/POST /workspaces/:id/students`                                           | 名单与新增学生                                                  |
| `PATCH /workspaces/:id/students/:studentId`                                   | 修改本期信息、转出或恢复                                        |
| `DELETE /workspaces/:id/students/:studentId`                                  | 按当前语义删除本期记录                                          |
| `GET/POST /workspaces/:id/assessments`                                        | 测评配置，修改和删除使用单项接口                                |
| `PATCH /workspaces/:id/scores/batch`                                          | 带预期版本和幂等键的成绩批量更新                                |
| `GET/PUT /workspaces/:id/references`                                          | 历史参照管理与版本校验                                          |
| `POST /workspaces/:id/promote`、`POST /workspaces/:id/transfers`              | 升学期、转班事务                                                |
| `GET/PUT /workspaces/:id/documents/:kind`                                     | 通知单、排表、学情等分项版本更新                                |
| `POST /imports/preview`、`POST /imports/:id/commit`                           | 日常 Excel 等业务导入的校验预览与确认执行，不提供整账号备份恢复 |
| `POST /attachments`、`GET /attachments/:id/content`                           | 附件上传、受控下载                                              |
| `POST /ai/:scene`                                                             | 已定义 AI 场景调用，可使用流式响应                              |

评语、标签、用户设置和草稿另设对应资源接口。错误格式统一包含 `code`、`message`、`requestId` 和必要的校验/冲突信息；不返回 SQL、密钥或服务器堆栈。

教学业务接口统一支持可选 `X-Managed-Account-Id` 请求头，由前端请求层附加 UUID。未携带时操作本人数据；携带他人 ID 时，后端验证 `ADMIN + account.manage-data` 并生成访问上下文。该头只是请求范围，不是身份凭据；普通账号伪造他人 ID 必须拒绝。不另建一套超级 VIP 成绩/学生接口，不在服务端会话保存全局当前目标，避免不同标签页或设备相互影响。认证、本人资料、账号管理、AI 凭据接口拒绝代管头，防止代管教学数据扩展为修改他人账号身份。

浏览器刷新令牌 Cookie 在生产启用 Secure、HttpOnly、SameSite；使用 Cookie 的刷新/退出接口检查 Origin 和 CSRF，业务接口使用 Bearer Access Token。认证生命周期、禁用即时生效和移动端适配见第 15 节。退出登录清理用户业务缓存及未提交操作，避免其他账号继承草稿。

## 8. AI 与附件

现有 `src/ai/providers.ts` 等直接从浏览器发送 AI 请求。服务器版浏览器只调用业务场景接口；提示词拼接、提供商访问、超时、取消和错误处理移到后端。

第一版默认使用管理员统一配置的模型与分配的累计 Token 额度，普通账号无需配置 Key；管理员可追加或扣减可用余额，不自动按月重置，输入与输出都计入消耗。账号也可显式选择自己的 Key，不扣平台额度，两种模式不自动回退。使用服务器环境密钥加密保存，查询配置只返回“已配置”状态。密钥不进入 VITE 环境变量或普通日志；运维数据库备份只含密钥密文，服务器恢复需另行管理加密主密钥。服务端密钥变量不使用 `VITE_` 前缀。

原有自定义 baseUrl 在服务器上改为管理员允许的提供商地址，阻止访问本机、内网和云元数据地址；限制请求尺寸、调用频率及并发。批量 AI 的结果写入时校验发起时的工作区及记录版本，避免覆盖用户后续修改。

附件使用不可变存储名称和摘要校验；用户名称仅作展示。上传先写临时文件，完成校验后发布，再提交元信息；失败文件定期清理。删除文件延迟回收，避免数据库引用与文件操作不一致，并为备份保留需要的文件。

## 9. 旧数据迁移、备份与回退

### 上线前一次性旧数据迁移

复用现有 Dexie 备份读取和归一化逻辑，支持 V5 完整备份；旧版单工作区备份沿用既有默认班级/学期兼容规则。使用受控运维迁移工具，不作为服务器版普通用户或管理员代管的日常恢复入口。迁移不能导入管理员角色、超级 VIP 标志、手机号、密码或登录状态；服务器账号权限不受旧数据影响。

1. 在本地版保存完整备份，停止编辑待迁移的数据。
2. 独立迁移工具读取备份并转换为有版本的迁移格式；写入服务独立重复校验，不能信任转换结果。
3. V5 当前活动期使用 main 实时业务表作为权威；其他期使用各自快照，当前期旧快照不能覆盖实时数据。
4. 生成预览：班级、学期、名单、成绩、引用、附件数量，以及空值、重复身份、未知字段和无效引用报告。
5. 上传附件到临时区，校验文件摘要和引用完整性；发现不支持的字段或附件编码时阻止提交，不能静默丢弃。
6. 审核迁移预览后通过受控命令，在事务内提交业务数据和附件引用，记录摘要与幂等结果；要求目标账号业务数据为空。
7. 目标账号非空则拒绝迁移，不提供自动替换或清空选项，不按姓名自动合并；需要重新迁移时单独制定运维处理方案，不能覆盖上线后的新数据。
8. 比较导入前后名单、成绩、满分、历史名次、参照、评语、标签、通知单、排表和附件，完成验收后才使用服务器版本编辑。

迁移过程不清空、不回写当前真实浏览器数据库。预览到提交期间的状态变化必须重新检查。大备份可以异步处理，但第一版先明确文件与记录数量上限，并提供可操作的错误报告。

### 运维统一备份与恢复

服务器版不提供整账号备份下载、恢复或一键清空按钮/API；原设置中的本地系统备份与清空入口移除。日常仍允许按业务规则删除学生、测评和学期，以及导入/导出 Excel、PDF 等教学资料。

运维使用 SQLite Online Backup API 生成一致数据库副本，加附件清单、对应文件与部署版本；加密主密钥单独备份。建议每日一次、保留最近 7 份与最近 4 份周备份，副本存另一位置，实际频率按可接受的数据损失调整。灾备包含全部账号，访问受限；恢复通过受控运维流程执行，不通过用户业务接口替换数据。恢复后撤销已有登录，要求重新登录，防止旧备份中的会话重新生效。

运行中不能仅复制 `.db` 文件当作完整备份。备份清单确定后，附件清理任务保留其中所有不可变文件，确保库与文件可共同恢复。恢复先在独立目录验证数据库完整性、外键及附件摘要，再进入维护状态替换。

代码回退与数据回退分别处理。保留 V5.0 原分支和迁移前备份；服务器开始编辑后，旧备份不能代表最新数据。若需回到本地版，必须额外实现并验证兼容 V5 的反向导出，不能仅切回旧分支。每次数据库升级前保存灾备，破坏性迁移未验证恢复不得上线。

## 14. 账号管理、超级 VIP 与防提权

### 14.1 账号操作

- 用户主键使用不变的 UUID；手机号是唯一登录名，以字符串存储、规范化后查重，不能用作业务外键。初期按中国大陆手机号支持，保留国际区号扩展位置。
- 手机号登录不等于短信验证。第一版使用手机号 + 密码，不引入短信服务；手机号由管理员核对。手机号修改仅允许管理员操作，并撤销目标账号全部登录；用户可修改自己的昵称和密码。
- 创建时自动生成如“老师\_7K4Q”的默认昵称，允许管理员填写；昵称不作为唯一身份，不直接拼接手机号。显示昵称时以纯文本渲染，长度建议 2–30 个字符。
- 管理页支持手机号/昵称搜索、分页、状态筛选、创建、编辑昵称/手机号、启用/禁用、重置密码、删除普通账号。手机号完整显示限管理页与本人账号页，普通教学页面优先使用昵称。
- 密码采用 Argon2id 等成熟实现，允许密码管理器粘贴；按用户要求不设密码复杂度和长度下限，只禁止空白和纯数字，接口最多接受 128 字符；不定期强制改密。
- 创建或重置生成一次性初始密码，仅在当次操作展示，管理员负责交付；服务端只存哈希，日志和列表不含密码。首次登录只能修改密码和退出，改密后重新登录才能访问业务。
- 用户改密验证当前密码；管理员重置无需知道旧密码，但需近期重新认证。修改/重置密码、禁用、删除均在事务中更新 authVersion 并撤销登录，已有 Access Token 也立即失效。
- 删除采用软删除：撤销登录、隐藏账号及其业务数据，不立即级联清空成绩和附件；首版不做自动永久清除。恢复/手机号复用政策后续另定，软删除账号手机号仍保留唯一约束，避免误关联历史数据。
- 系统首个管理员在本机首次打开页面时填写手机号创建；系统生成随机临时密码供复制，首次登录强制改密。已有管理员时关闭新建入口；生产环境及远程连接通过交互式初始化命令创建，不在命令参数暴露密码。公开 API 不允许普通账号成为管理员；额外管理员通过受控运维命令创建。
- 所有管理员账号禁止删除、禁用、降级；UI 隐藏操作只是辅助，Service 和数据库约束/触发器共同兜底。管理员可自改密码和昵称，忘记密码通过受控运维命令恢复，不允许另一管理员通过普通用户接口绕过保护。
- 敏感操作记录操作者、目标用户、动作、时间、结果和 requestId；不记录密码、令牌、AI 密钥或完整业务请求体。

“超级 VIP”按管理能力命名，界面建议使用“账号代管”，不做支付、订阅、普通会员等级或给普通账号升级的功能。管理员在自己的管理设置中重新验证密码后开启/关闭，写入审计；后台配置明确显示当前权限状态。

顶部导航顺序为“账号 → 班级 → 学期”。普通账号不显示账号选择器；管理员开启代管后显示可搜索、分页加载的账号选择器，默认“我的账号”，支持一键返回本人。选项展示昵称及必要的手机号尾号，避免同名混淆；软删除账号不列入代管选择，禁用账号可标明状态并允许管理员维护业务数据，不恢复其登录能力。

切到目标账号后，原成绩、学生、评语、通知、排表、草稿及业务附件页面加载对应数据，沿用现有操作流程。顶部持续显示“正在管理：张老师（手机号尾号 1234）”；本人资料始终属于真实登录管理员。账号禁用、重置密码和删除等身份操作仍放在账号管理页，不跟随业务切换。

切换流程：检测当前草稿 → 用户保存或确认放弃 → 等待已提交写入完成（失败则留在原账号）→ 取消可取消的读取/生成任务 → 清理缓存、选中项和预览 → 加载目标账号 → 校验加载代次后展示。加载失败不能以空数据覆盖目标账号；显示错误并允许重试或返回本人。账号选择按页面实例保存，不写服务器全局状态；不同标签页可代管不同账号。

删除学生、删除学期和批量删除时，确认框必须显示目标账号、班级/学期及影响范围；不提供整账号恢复备份或清空入口。业务导入任务、幂等键、教学导出、下载链接及文件发布绑定创建时的 owner；切换后不能把原账号的任务提交到新账号。幂等回执同时校验 actor、owner 与请求摘要。

代管不读取目标账号 AI 密钥；在目标业务中调用 AI 使用真实操作者自己的提供商配置，并提示费用归属，结果写入原目标账号前仍校验版本和当前授权。其他用户级偏好/版式按业务范围明确加载，主题等设备偏好保留管理员设备设置，不覆盖目标账号的私人设置。目标账号 AI 凭据页面不展示也不能代改。

### 14.3 接口隔离

1. 每次请求由后端令牌解析当前 actor，查询账号状态、authVersion 与权限；请求 body 中的 userId/ownerId/role/VIP 字段不能改变 actor。代管头通过集中策略解析为 owner，普通用户只能选择本人；VIP 授权关闭后他人访问立即拒绝。
2. 自改资料 DTO 只允许 nickname 等白名单字段；管理 DTO 也不能写入密码哈希、管理员角色或任意权限。未知敏感字段直接拒绝，防止批量赋值提权。
3. 所有业务 Repository 要求显式 owner 范围，SQL 条件与关联查询带归属限制；管理员代管也不得省略。对工作区、学生、测评、附件、导入任务等均验证完整关系，防止只校验外层 workspaceId。
4. 无权限资源一般返回统一 404，避免泄漏记录是否存在；统计数量、搜索、分页、冲突详情、下载和导出同样受归属策略约束。
5. 查询、编辑、删除等共用业务接口和数据访问上下文；他人数据上下文显式要求 `ADMIN + account.manage-data`，不生成他人身份令牌，不接受上下文外的任意 asUserId/ownerId。账号资料、认证及密钥接口不允许代管上下文。
6. 权限变更立即查询生效，不把客户端缓存或长效 Token 中的角色当作最终授权。缓存按 actor、owner 范围及工作区分开，关闭 VIP 或退出后立即清除跨账号视图数据；长任务提交前重新检查授权。
7. 跨账号访问记录查询范围和目标工作区，写入记录动作、资源 ID、结果及 requestId；不逐条复制学生成绩到日志。代管写操作审计与业务变更在同一事务中保存，业务数据删除需明确确认目标归属。

## 15. 统一认证及未来客户端

### 15.1 为什么调整

Session 本身并不低级，Cookie 传输也不局限于桌面浏览器；手机 Web 可以直接使用同一 Cookie 认证。真正需要提前统一的是身份验证、登录续期、撤销与业务授权。考虑未来小程序，第一版选择统一 Bearer Access Token，客户端差异仅在 Refresh Token 的存储和传输。

由于后端是单实例且需要即时禁用，第一版推荐高强度随机不透明令牌（opaque token），数据库只存摘要，而不是为了 JWT 的“无状态”省略撤销检查。令牌生成、比较和密码哈希使用成熟库，不自写密码学。

### 15.2 生命周期

- Access Token 默认有效 1 小时（60 分钟，3600 秒）；登录建立设备会话，业务请求携带 `Authorization: Bearer ...`。令牌不得出现在 URL。
- Refresh Token 默认有效 7 天、每次使用轮换，登录族有绝对期限，不能无限滑动续期；“记住登录”默认不启用，若增加再审核更长期限。
- 每次访问检查 Access Token 摘要、有效期、所属设备会话是否撤销、用户是否启用，以及 authVersion 是否匹配。业务权限从服务器当前状态读取。
- Web：Access Token 只保存在内存；Refresh Token 存同源 Secure、HttpOnly、SameSite Cookie。页面刷新通过续期恢复，Token 不进入 localStorage。
- 未来小程序/移动客户端：Access Token 同样放内存，Refresh Token 按平台能力存储，使用明确的刷新协议；小程序存储不能视为硬件安全存储，控制期限和设备撤销。Web 刷新接口不返回 Refresh Token 到响应正文。
- 第一阶段只开放 Web 刷新通道；第二阶段新增客户端传输适配，复用同一个认证 Service，不改变账号、权限和业务 API。clientType 仅决定传输策略，不能提升权限。
- Refresh Token 使用数据库条件更新和事务原子轮换；旧令牌再次使用触发令牌族撤销与审计。前端单次刷新合并，多标签页协调；其余请求重试时使用新 Access Token。响应丢失则允许要求重新登录，不以重复接受旧令牌换取便利。
- 退出撤销当前设备；“退出所有设备”、密码变更、禁用、删除撤销所有设备。管理员保护不豁免登录限流和令牌撤销。
- 改密前强制未完成账号只拥有独立受限认证权限，不能通过直接调用业务 API 绕过首登改密。

### 15.3 小程序接入边界

第一阶段不实现微信登录、AppID 配置或手机号自动绑定。后续增加微信身份适配器，将平台验证后的身份关联到现有 UUID 用户，再颁发同一套业务令牌。微信身份、手机号展示和业务账号不能凭客户端上报内容自动合并；绑定需要现有账号验证，解除绑定也需重新认证。

小程序合法域名、HTTPS、平台隐私授权及登录接口要求在接入阶段按当时官方文档核验。此次无需引入完整 OAuth 授权服务器，未来需要第三方登录时再增加受控适配。

## 16. 登录页、滑块及防暴力破解

登录页复用系统现有 `--surface-page-gradient`、`--surface-card`、`--text-primary`、主题主色及 Element Plus 控件，采用轻背景、圆角卡片和现有页脚风格。桌面居中登录卡片，展示系统名称、简短说明、手机号、密码显隐、滑块和登录按钮。匿名用户使用默认主题或该设备主题，不读取前一账号的私人设置。

支持标签、键盘焦点、密码自动填充，登录中防止重复提交；表单错误与网络错误分别显示。自建账号无公开注册，忘记密码提示联系管理员。手机常用工具的布局优化放第二阶段，但登录页不写死超宽尺寸。

滑块不是纯前端“拖到终点就通过”：

1. 后端生成随机拼图挑战 ID、图片和短期有效期，正确位置/校验资料只在服务端保存。
2. 前端提交拼图位置及必要交互参数，后端验证位置、挑战有效期和使用状态；轨迹仅作辅助，不作为不可伪造的依据。
3. 验证通过后颁发短期、一次性登录票据，绑定本次挑战与登录意图；登录接口原子消费票据，不能通过伪造 passed=true 绕过。
4. 挑战建议有效 120 秒、通过票据有效 60 秒；失败次数受限，可刷新挑战。每次尝试登录后需要新票据，无论密码是否正确。
5. 第一次登录也要求滑块；登录、挑战创建、校验、刷新等端点各有限流，避免攻击者只攻击验证码生成或令牌续期。
6. 初始可采用 IP 每分钟 10 次登录尝试、账号 15 分钟 5 次失败后短时冷却并逐步增加等待，结合设备维度与部署环境调优；不永久锁死账号，不让单一账号限制成为攻击他人的长期拒绝服务手段。
7. 相同的“手机号或密码错误”响应覆盖账号不存在、禁用等情况，控制差异，降低账号枚举风险；审计中记录具体原因。反向代理仅信任配置的代理来源，不能信任任意 X-Forwarded-For 绕过限流。

提供键盘可操作的滑块及刷新/错误提示；实施时验证可访问性。如需要非视觉替代验证，需采用同等服务端防护的方案，不能增加一个免验证码入口。拼图资产使用小尺寸本地素材，不新增大图片或字体包。

验证码模块采用可替换 Provider 接口，第一版本地拼图实现保持无外部服务依赖，且不能承诺抵御高级自动解题；后续遭遇持续攻击时可替换成熟托管服务。限流、密码策略、撤销和审计始终保留，滑块只增加暴力破解成本，不能独自防止攻击。

## 17. Python 一键启动脚本

交付 `start.py`，命令为 `python3 start.py`（Windows 可使用 `py start.py`）；入口短小，具体功能拆到 `scripts/dev_launcher/`。用于本地开发启动，不把端口强制释放策略用于生产部署。

启动流程：

1. 检测操作系统、Python、Node.js、pnpm 及项目要求的版本，缺少运行时给出中文安装步骤，不擅自安装系统软件。
2. 检测工作区依赖和关键本地二进制、锁文件指纹；缺失或与锁文件不一致时，运行根目录 `pnpm install --frozen-lockfile`。不修改锁文件，不删除/清理 node_modules，不自动升级包；安装失败立即停止并显示具体错误。
3. 初次从 `.env.example` 生成开发配置，只补缺失文件，不覆盖已有密钥、端口或数据库路径。本机网页自动进入首次管理员设置流程，每次安装生成独立的临时密码，不使用固定通用密码。
4. 读取 ui/server 配置端口（建议前端沿用 5173，后端 3000），校验两者不同、合法且一致使用；默认只监听本机，第二阶段手机调试另提供显式局域网参数。
5. 查找配置端口的所有监听进程，显示 PID、进程名及释放日志，直接自动结束后再启动，不额外询问、不仅限本项目旧进程。优先优雅停止，超时后强制结束，确认端口释放后继续；不宽泛杀掉全部 node/python 进程，不把 PID 文件当作唯一证据。
6. 终止前重新核验 PID、启动时间和当前监听端口，防止 PID 复用误杀；仅针对配置端口的实际占用者，不能扩大为同名进程批量结束。没有操作系统终止权限、进程信息无法可靠确认或端口无法释放时，报告具体原因并停止，不擅自提权、不伪装成功；进程被终止可能丢失未保存状态，启动文档明确说明默认行为。Ctrl+C 清理仅涉及本次脚本启动的子进程。
7. 校验开发数据库 schema，必要时执行已提交的迁移；已有库迁移前备份。迁移失败不继续启动 UI，不自动重置数据库。
8. 启动后端并通过就绪检查，再启动前端；端口争用、子进程提前退出或超时均报告，清理本次进程，不伪装启动成功。
9. 输出前后端地址、日志位置和停止方式；监听任一服务异常，避免只剩一个进程长期运行。

脚本参数至少包括 `--check`（只检测）、`--no-install`（禁用自动安装）、`--no-release-ports`（不终止端口占用者）和 `--help`。用户运行默认脚本代表执行其已说明的本地安装/释放流程；本次审核不实际执行脚本。代理不能把“编写脚本”当作现在安装包或结束用户进程的授权。

跨平台实现只调用明确的系统工具或已声明依赖，命令参数使用 subprocess 数组而非字符串 shell 拼接。端口检测工具不存在时报告安装方式，不自动安装。测试通过模拟进程、临时监听端口及临时配置完成，不关闭用户真实服务。

## 18. 第二阶段手机工具与维护规范

### 手机阶段

首阶段接口不依赖桌面路由、全局当前工作区或 Cookie 之外的浏览器业务状态。第二阶段采用同一 ui 工程的手机布局与共享 API，优先实现登录/个人资料、班级学期选择、学生与成绩查询、快速录分、名单/座位表/值日表等常用功能；具体工具优先级届时审核。

手机功能按屏幕宽度适配，不通过 User-Agent 决定权限。大表配置、复杂打印和版式编辑先保留桌面入口。小程序需单独客户端工程，不能将 Vue 桌面页直接当作已完成小程序实现。

### 文件拆分与中文注释

- 按业务模块组织账号、认证、工作区、成绩、VIP、导入和工具，路由只负责 HTTP，Service 负责业务，Repository 负责 SQL；避免一个 controllers.ts 或 stores.ts 承载全部业务。
- 单文件接近 300 行或单个函数接近 60 行时触发拆分审查，按职责判断，生成文件/SQL/固定数据单独处理；不为行数机械切碎代码。
- Vue 大页面拆为页面壳、功能组件和 composables；Python 拆为依赖检测、配置、端口、进程及日志模块。
- 导出的业务函数、组合式函数、权限策略、迁移转换和启动辅助函数提供中文 JSDoc/docstring，解释用途、输入/返回、失败情形；复杂事务注释说明一致性与回滚原因。
- 为新人说明 opaque token、ownerId、version、幂等、WAL 等术语在本项目中的作用；不逐行重复语法，注释随代码同步更新。
- 不新增大二进制、内嵌 base64、重复素材或数据库备份到仓库；文件上传与导入限制大小、分批转换，校验依赖是否引入不必要的资源。
