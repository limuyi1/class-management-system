# 服务器班级、学期与名单

本说明对应 node-sqlite-migration 分支的阶段性实现，不能替代最终迁移说明。

## 页面操作

登录后进入「班级与学生」。首次使用创建班级和学期，随后新增学生。编辑名单可以改名、禁用或标记转出；删除采用软删除，历史行保留，目前没有恢复页面。

「进入新学期」保留班级长期 ID，可以修改新学期班名。勾选沿用名单时只复制未转出、未删除的学生及其禁用状态；也可勾选沿用测评配置。往期班名、姓名和状态保持原样，不复制成绩或评语。

先建立同名学期的另一个班级，编辑学生时即可选择目标并转班。来源名单标记转出，目标添加空的本期名单；两步在同一事务完成，失败全部回滚。

管理员在「个人设置」开启账号代管后，可在名单页顶部搜索并选择账号。提示条显示目标昵称和手机号尾号，所有名单修改作用于所选账号；账号管理和本人密码操作仍作用于真实登录者。关闭代管后立即返回本人数据。

## 表与身份

- users：真实账号与身份权限。
- classes：某账号的长期班级身份。
- workspaces：班级在某学期的名称、满分和版本。
- students：某账号的长期学生 ID，不以姓名判断身份。
- enrollments：本学期姓名、禁用/转出状态、软删除时间及行版本。
- mutation_receipts：写入幂等结果，绑定真实操作者、目标账号与请求键。

工作区与名单使用包含 ownerId 的复合外键。API 请求和仓储也独立检查 owner；不能只依靠 UUID 难以猜测防止越权。

## API 契约

所有接口前缀为 `/api/v1`。认证使用 Authorization Bearer；业务范围使用 `X-Managed-Account-Id`，本人也可以显式传自己的 ID。普通账号不能传其他人的 ID，管理员必须开启代管资格。

| 方法           | 路径                                         | 用途                                            |
| -------------- | -------------------------------------------- | ----------------------------------------------- |
| GET            | /admin/managed-accounts?search=关键词&page=1 | 管理员代管账号摘要搜索，每页最多 50 条          |
| GET / POST     | /workspaces                                  | 读取目录 / 新建班级学期                         |
| PATCH          | /workspaces/:id                              | 修改本期名称/满分，必须携带 version             |
| GET            | /workspaces/:id/state                        | 同一数据库事务读取本期目录与名单                |
| GET / POST     | /workspaces/:id/students                     | 读取 / 新增学生，可显式指定本账号历史 studentId |
| PATCH / DELETE | /workspaces/:id/students/:studentId          | 编辑 / 软删除，需要当前名单 version             |
| POST           | /workspaces/:id/promote                      | 进入新学期，需要源工作区 version                |
| POST           | /workspaces/:id/transfers                    | 转班，需要 studentId、targetId 与学生 version   |
| GET            | /students/history                            | 当前账号可显式复用的历史学生身份                |

所有业务写入必须提供 `Idempotency-Key`（8–128 位字母、数字、下划线或短横线，推荐 UUID）。网络超时重试使用原键和原内容；修改内容要换键。相同键对应其他动作/内容返回 409；相同内容重试返回首次结果，不重复写入和审计。

编辑遇到 `VERSION_CONFLICT` 时刷新后核对最新资料，重新编辑；不要自动用旧值覆盖。写请求发起时已捕获账号 ID，页面切换不会改变其归属。只读响应同时检查账号与加载代次，防止旧响应污染新名单。

成绩录入、测评配置与历史参照见 [服务器成绩与历史参照](./server-scores.md)。
