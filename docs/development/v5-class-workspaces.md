# V5.0：本地多班与学期工作区

## 使用方式

V5.0 保留原有成绩录入、学生信息和总览页面。顶部增加班级、学期两个选择框和「管理」入口，不需要服务器、登录或云同步。

### 同时带多个班

在「管理 → 创建另一个班级」填写班名、学期。新班从空名单开始，可以单个新增或导入 Excel。班级选择框会记住各班上次打开的学期。

同一学期不能使用重复班名，同一班级不能创建同名学期。建议各班统一使用例如「2026–2027 上学期」的学期名称，便于转班。

### 303 升为 403

1. 打开 303 的来源学期。
2. 选择「管理 → 进入新学期 / 升班」。
3. 填写新班名 403、新学期，选择是否沿用学生名单、单元配置及历史参照。
4. 创建后，在学生信息页添加转入学生、将离开的学生标为「本期转出」。

沿用名单保留学生 ID 和禁用状态，不带入成绩、评语及学生表现标签；已转出学生不自动进入新学期。沿用单元保留单元名称、启停状态、单列满分、标签分类及可选标签，但成绩留空。

去年仍显示 303 及当时的数据，今年显示 403。修改本期班名不会改写往期班名。

### 人员异动

- 「本期转出」保留已有成绩、评语及往期记录，不参与在班统计和后续录入；可以「恢复在班」。
- 「转到其他班」选择另一班的同名学期，沿用学生 ID，来源保留成绩，目标从空白成绩和评语开始。
- 「从历史名单加入」找回本班往期已有的学生，保留 ID。没有历史身份的新学生正常新增。
- 同名学生不能仅凭姓名当作同一个人；历史参照按 ID 连接。
- 原有「删除学生」仍是永久删除当前学期该学生及相关业务引用，不等同于转出，不删除往期快照。

### 历史参照与总览

进入新学期默认引用来源学期最后一列有成绩、已启用的单元。这里只引用来源，不复制成绩。可以在总览页「更换参照」，选择本班其他学期的成绩列，或全部取消。

成绩录入页只显示当前选择的本期单元，不展示历史参照或参照设置。历史参照仅用于总览、趋势和学习报告；修改来源成绩须打开原学期。单元配置仅列出成绩单元，基础姓名字段不作为单元展示。

| 项目                                 | 计算范围                                   |
| ------------------------------------ | ------------------------------------------ |
| 本期均分、及格率、分数段、完成单元数 | 本期已启用的成绩列                         |
| 连续趋势、进步与下滑信号             | 历史参照 + 本期成绩                        |
| 历史名次及学习报告的历史班均         | 来源学期原名单中的有效成绩                 |
| 当前关注名单                         | 本期在班且本期已有成绩的学生               |
| 难度修正                             | 本期成绩内部；不把历史参照作为本期难度基线 |
| 稳定前列                             | 本期名次，不把跨期名次直接作为连续前列依据 |

每名学生分别判断有效次数。转入、缺考、未录入保持空值，零分属于有效成绩。三次成绩相关的规则需要该生实际有三次有效成绩；少于三次仍提供基础统计和允许少量数据的信号。

总览和学习报告按测评满分换算为百分制；成绩表和录入保留原始分。单元可单独设置满分，未设置时使用本期默认满分。成绩页单列均分保留原始分，优秀率、及格率等按满分比例计算。

百分制换算不能消除试卷内容、年级和难度差异，跨期趋势只作参考。图表标出历史参照与本期分界；AI 分析明确接收数据范围和参照来源。

本期成绩按单元配置的顺序分析；历史参照按学期目录顺序、来源成绩列顺序排列。请按测评先后维护单元顺序。

### 座位表与值日表

新学期从空排表开始，在班级管理中可以沿用上期座位表、值日表。之后按当前名单校对并调整。独立 Excel 来源的排表名单保持原样。

### 切换与临时编辑

切换前等待 Store 初始化和持久化写入，再通过数据库事务保存原期快照并加载目标。失败时事务回滚，当前数据不被替换。

成功后重新加载页面，清理路由缓存、学生选择、预览和未提交表单。请先保存正在编辑的表单或预览内容；写入 Store 的成绩、名单等会自动保存。

同一浏览器的多个标签页共享当前工作区。其他标签页会刷新到新选择；旧页面的持久化写入经过工作区版本校验，不能覆盖新班级。

## 升级与旧数据

首次打开 V5.0 自动建立「默认班级 / 当前学期」，现有业务数据原地保留，不猜测班名或历史成绩归属。

日常管理不再提供「整理历史成绩」「所有列均属于本期」入口或升级整理提示。已有历史数据通过准备好的完整迁移备份一次性恢复，之后直接切换学期查看，不需要逐列整理。

迁移备份按原成绩列顺序划分学期，无学期前缀的列归入前面最近一个明确学期。学生身份沿用原 ID；转出学生保留在历史名单，新转入学生只进入本期，不补造历史成绩。本次个人迁移保留原评语和标签到当前名单，同时在历史学期留档；吴承宇在当前名单作为已转出记录可见，不计入56名在班学生。此处理不改变日后新建学期默认清空评语和标签的规则。

恢复路径：设置 → 系统备份 → 选择备份。导入完成后，顶部选择当前班级和学期即可使用。日常管理保留进入新学期／升班、创建另一个班级、沿用往期排表、修改名称和删除学期；总览页继续提供历史参照设置。

底层旧列整理服务保留用于迁移工具与兼容性验证，不在日常界面暴露。

## 备份、恢复与删除

- 完整备份包含全部班级、学期、业务快照、参照关系和当前选择。
- 当前工作区的实时业务表是权威数据，导出前同时更新当前快照。
- 导入旧版单套备份时，自动建立默认班级和学期；导入会替换整个系统，而非仅当前班级。
- 清空系统会清空所有班级和学期。
- 删除学期会删除该期名单、成绩、评语、通知单及排表，需明确确认；当前学期不能删除。
- 被其他学期用作参照的学期或成绩列不能直接删除，须先取消参照。

V5 数据库增加了目录和快照表。V4 应用不支持 V5 数据库结构；切回 V4 代码不会自动降级数据库。回退前应使用独立浏览器站点数据或恢复升级前的 V4 备份，保留 V5 完整备份。

## 实现结构

数据库 schema 版本从 4 升为 5，新增：

- `workspaces`：班级、学期目录、当期名称、上次选择、参照关系和工作区版本。
- `workspace_snapshots`：各期的名单、成绩列与标签配置、成绩通知、座位表、值日表、学情分析及业务偏好。

原来的 `main` 业务表作为当前工作区，现有录入、导入和业务服务继续操作原 Store。离开工作区时在事务内保存业务快照，再恢复目标快照。这是为保持现有功能兼容而选择的本地工作区实现，不引入多套教学、任教、考试管理界面。

全局共用：AI 配置、主题、字体、导出版式、错题库、附件和版纸草稿。当前录入列、近期录入记录、默认满分跟随学期保存。

主要入口：

- `src/utils/workspaceUtil.ts`：初始化、事务切换、创建、改名、转班、旧列整理与备份检查点。
- `src/utils/workspaceScoreUtil.ts`：原始分展示、ID 关联、历史排名及百分制分析投影。
- `src/stores/workspace.ts`：目录与历史快照缓存。
- `src/components/workspace/`：顶部选择器、参照设置、名单异动入口。
