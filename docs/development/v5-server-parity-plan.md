## 1. 实施前核对结果与交付原则

- `ui/src/main.ts` 在服务器模式加载 `ApiApp.vue`，仅显式 legacy 模式加载旧入口。
- `useWorkbenchNavigation.ts` 重新组织教学菜单，管理员仍获得教学菜单与个人 AI 菜单；`ApiApp.vue` 缺少对应组件的管理员身份限制。
- `WorkspacePanel.vue` 使用新建的 `AnalysisPanel`、`ScorePanel`、`TeachingPanel` 等面板，没有完整沿用原页面。总览为简化图表与表格，成绩为选择测评后按列录入。已存在后端能力不能据此认定旧版交互完整迁移。
- `ProfileSettings.vue` 和顶部均提供皮肤选择，存在重复入口。
- `AdminAISettings.vue` 展示账号搜索、账号选择及单账号余额调整，没有额度列表与添加弹窗；`adjustAIQuota` 未校验平台模型配置，也未排除管理员额度对象。
- 服务端业务归属校验允许本人 owner，尚不能作为“管理员本人无教学业务”的完整权限边界。

交付原则：保留 V5.0 老师菜单、路由、布局、组件、操作流程及导出版式，将数据访问和持久化改为 API。不得自行合并、改名或删减原功能，不以新面板代替原页面后宣布迁移完成。允许增加必要的加载、保存失败、版本冲突、权限失效反馈及登录/管理能力。

当前仅确认了入口与代表性页面差异，尚未完成全部按钮、字段、快捷操作及打印结果的逐项验收。以下表格是开发范围与验收清单，不是完成声明。

| 能力                                              | 管理员本人 | 普通老师      | 管理员完整代管老师             |
| ------------------------------------------------- | ---------- | ------------- | ------------------------------ |
| 账号管理、平台模型、额度分配、平台调用核对        | 允许       | 拒绝          | 拒绝                           |
| 班级、学期、课程/测评、学生、成绩、评语与教学工具 | 拒绝       | 本人数据      | 目标老师数据                   |

| 个人资料、密码、设备、皮肤                        | 本人       | 本人          | 按现有完整代管规则使用目标身份 |
| 认证刷新、退出、代管控制、审计 actor              | 真实身份   | 真实身份      | 真实管理员身份                 |

管理员菜单顺序建议为“账号管理、平台 AI 与额度、登录设备、个人设置”，默认账号管理；首登改密仍仅允许个人设置。老师主菜单严格按第 2 节，管理员代管老师使用同一套路由、页面和数据访问实现。

实现要求：

1. 菜单权限、导航回退与组件挂载共同限制，管理员本人不初始化教学 store、不请求工作区和个人 AI，不仅隐藏菜单。
2. 在服务端集中新增教学有效用户策略，分别接入教学查询、写入、AI、文件/导出及离线教学导入的业务入口。不要修改通用身份校验导致管理员平台管理和个人资料不可用。
3. 管理员本人教学请求返回 403；有效 owner 必须为老师。完整代管校验真实设备会话、目标状态和权限，审计保留 actor/owner。
4. 保持 `X-Managed-Session` 完整代管、旧业务范围头的已有兼容边界；旧范围头不能访问个人身份/密钥接口，不能成为创建管理员自身教学数据的绕过路径。前端统一使用完整代管。
5. 账号/学期切换销毁或清理旧缓存和临时状态，提交中阻止切换，晚响应丢弃，离开草稿确认继续有效；失效会话清空目标内容并返回管理员。
6. 只读检查管理员名下残留教学数据、个人 AI 和额度并形成清单。不自动删除、转移或扣回历史额度；如存在残留，单列数据处理方案审核，不写入普通前端回退逻辑。

## 5. 平台 AI 与账号 Token 额度

### 5.1 模型前置条件

建议规则：平台服务地址、模型名称、Key 均已保存，且 AI 已启用，才允许首次添加或追加额度。配置完整与真实模型连通是不同状态，本轮不自动调用付费模型做分配前置测试。现有 `configured` 仅表示 Key 存在，校验应同时覆盖其他字段和启用状态。

- 前端禁用“添加账号额度/追加”，显示“请先配置并启用平台模型”，提供模型配置页跳转。
- 后端在额度事务提交时检查同一规则，配置加载失败也不能默认允许提交。
- 未配置/停用时仍可查看额度和账单、扣减余额、核对历史调用；不能新增或追加。
- 删除 Key、停用、更换模型不清空原余额、预占、消耗与流水。额度为账号级累计 Token，不绑定某次模型配置，不按月重置。
- 核对超预算账单但余额不足、平台又不可用时，提示先恢复配置再追加；不能通过账单核对绕过余额约束。

上述“完整并启用”的条件比“没有配置不能添加”更具体，为待审核建议。

### 5.2 列表与弹窗

“账号 Token 额度”主体是分页列表，顶部包含搜索、账号状态筛选、刷新和明显的主按钮“添加账号额度”。搜索按手机号/昵称筛选列表，账号选择不占用主列表位置。

| 列表字段                         | 说明                                                  |
| -------------------------------- | ----------------------------------------------------- |
| 手机号、昵称、账号状态           | 老师账号摘要                                          |
| 可用 Token、预占 Token、累计消耗 | 保持现有 available/reserved/used 口径，整数千分位展示 |
| 操作                             | 追加、扣减，独立弹窗                                  |

默认展示已存在 `ai_quotas` 记录的未删除老师账号，包括零余额、禁用状态；自动预占生成的零额度记录也可以出现，不新增额外“已分配”状态。无记录时展示空态及添加入口。已删除账号不出现在默认分配列表，历史账单与审计继续保留。

添加弹窗：可搜索的老师账号选择、当前余额摘要、正整数 Token 数量、必填原因。选择范围限定有效老师；管理员、已删除及禁用账号不可新增/追加。已有额度的账号仍可添加，语义为追加，同账号始终只有一行。行内扣减采用正整数输入，后端转换成负 delta，禁止可用余额为负或扣除已预占余额。禁用老师允许管理员扣减既有可用余额，不能追加。

提交中禁用重复提交和关闭；成功关闭并刷新列表，保留筛选，必要时提示当前筛选未包含目标；失败保留输入。请求超时重用原幂等键；切换账号、修改数量或原因后生成新键。409 冲突重新获取余额与版本，保留草稿供核对，不自动重发覆盖。弹窗未保存草稿纳入页面、标签和账号切换检查。

### 5.3 API 与数据实现

- 拟新增 `GET /api/v1/admin/ai/quotas?page=1&pageSize=50&search=...&status=...`，服务端联合账号与额度分页，返回 `items/total/page/pageSize`，每项含账号摘要及额度 version；稳定排序，pageSize 上限 50，避免逐账号请求。
- 复用单账号额度查询与 `POST /admin/users/:id/ai-quota`，保持 `{ delta, version, reason }` 和 Idempotency-Key。未建立记录查询为零余额 version 0，不在读取时写入。
- 事务内验证管理员权限、有效老师对象、追加前置配置、数量/原因、版本及余额上限。额度更新、流水、审计、幂等回执同事务，真实模型用量仍只由服务器取得。
- 列表、详情和操作使用共享 DTO，增加中文业务注释。本项预计复用现有 schema；若需新增字段或索引，先说明原因并同步 SQL、Drizzle 与结构测试。
- 平台模型配置、额度列表、添加弹窗、调用记录拆分职责，避免继续扩大 `AdminAISettings.vue`。

## 6. 原页面接入 API 的实现路径

### 6.1 页面与数据层

1. 将原教学路由接入认证后的服务器工作台，复用 `MainPage`、`LeftMenu` 与原业务页面，接入账号菜单和完整代管。路由守卫改为服务器就绪状态与角色校验，不能原样加载 legacy router 的本地初始化守卫。
2. 为学生、测评、成绩、工作区、标签、教学文档、课堂方案、素材与账号偏好建立 API repository/adapter，复用已有 `hooks/api/` 和服务端接口。
3. Pinia 保留原页面所需接口及页面草稿，通过 DTO 投影适配原字段；稳定保存服务器 ID、版本和长期学生 ID，不用姓名或排序位置作为身份。
4. 查找原组件对 store 的直接赋值、Dexie 调用和自动持久化依赖，逐条改为明确业务提交；不能把“API 数据填进旧 store”当作完成写入迁移。提交成功再确认已保存，失败保留草稿，加载失败不写空默认值。
5. 服务器入口不注册 Dexie 持久化、不读取其教学缓存、不回退浏览器业务数据。旧入口仅用于显式 legacy 兼容及对照。
6. 业务配置、主题/字号、导出版式、临时选择按既有账号/设备/工作区作用域保存，避免切换学期或代管时错误共享。

### 6.2 业务与导出不变量

- 历史参照按长期学生 ID 连接，只读展示，不复制入本期学生对象；本期统计不含历史，连续趋势可含历史，历史排名按原名单，缺失为 null，零分保留。
- 学生禁用/转出、工作区软删除保留历史数据；跨账号不得读取、写入或导出。
- 后端统一统计、权限、导入预览/事务确认、版本、幂等、AI 提示与调用。前端保留图表、拖拽、裁剪、预览、DOM PNG/PDF 和打印版式，使用授权的一致快照。
- 导出时保留模板、图片版本、纸张、字体与分页，完成前重新鉴权并核对账号/工作区代次；批量导出限制和停止能力保留。不新增备份大字体依赖。
- 保留已迁入的历史通知及其他兼容数据的查看/导出能力，不因恢复旧页面失去访问入口；作为明确兼容补充记录。

完整职责参见 [前后端职责](./frontend-backend-responsibilities.md)。恢复原 UI 不意味着恢复旧数据库权限与写入模式。

## 8. 验收与验证节奏

### 8.1 必须验收的场景

- 管理员登录仅管理菜单；直接访问教学/个人 AI 路由回到允许页面，直接 API 查询、写入、AI、素材下载/导出均被拒绝；角色变化及残留 visited/cache 不绕过校验。
- 普通老师与管理员代管老师展示相同五项主菜单、工具中心、原页面；代管期间平台管理员接口拒绝。刷新恢复、草稿取消、返回管理员、目标禁用/改密/撤权及晚响应均正确。
- 个人设置不再有皮肤标签，顶部四种主题保存/刷新及代管前后恢复正确。
- 未配置、配置不完整、停用、配置加载失败时新增/追加被前后端拒绝；列表、扣减及账单核对仍可用。
- 首次添加、已有账号追加、余额归零、搜索分页、禁用/删除/管理员对象、非法数量、额度上限、扣减不足、版本冲突、超时重试和连续点击均按第 5 节执行。
- 原菜单折叠、高亮、深链接、设置 query、兼容路由、浏览器前进后退、空名单及初始化错误正常。
- 逐原页面核对布局、字段、按钮、键盘/批量操作、临时 Excel 数据来源、保存后重载、跨设备修改及断网草稿；禁止仅验收 API 响应。
- 用同一组隔离样本核对原页面与服务器版的统计、历史参照、零分/缺失、模板、通知及报告事实；检查导出内容、分页、长文本、拖拽和图片历史版本。

### 8.2 执行方式

功能阶段仅运行相关模块基本测试与必要类型检查/Lint；失败定向修复复验。P5 集中执行根 `pnpm test`、`pnpm build`、`pnpm lint` 与 diff 检查。历史全量结果不得写成本轮验证。

浏览器 UI、鼠标拖拽、打印分页及长报告单独验收，采用隔离合成数据，不操作真实账号和账单。遵守 AGENTS.md：未经明确安装/启动授权不安装依赖、不清理 node_modules、不启动开发服务器；验证环境不可用时保留未验收状态并报告。真实模型、真实数据迁移和部署环境验收另外记录。
