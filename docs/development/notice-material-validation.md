# 通知真实素材复刻验证

当前结果（2026-10-04）：已完成独立素材文档渲染，独立实验六组原始尺寸以及普通通知 2 倍 PNG 均与修复后的原通知零像素差异。以下首轮记录保留为问题定位依据；最新验收见文末。


日期：2026-10-04。范围：验证方案，未执行制作工作台合并或修改业务渲染代码。

## 结论

**现有通用文字/图片画布无法复现原通知，本轮素材复刻不通过。** 原通知作为内置模板，通过统一入口复用原渲染器可以保持一致；这只能证明入口合并可保留原效果，不能证明通用素材编辑器已具备同样的制作能力。

后续以原通知作为通用模板能力的验收标杆：素材、布局和变量均可复用，更换学生数据仍能生成相同风格的通知。不能把已填好学生资料的整张图片作为背景，也不能仅靠原通知专用渲染器宣称通用素材复刻完成。

## 实际测试方式

- 使用项目已有纸张底图、校徽、花纹、边框、彩带、月桂和教师评语徽章；使用现有默认手写字体和系统字体。
- 学生数据均为虚构，隔离 Pinia，不接入持久化或真实班级数据库。
- 原版与模板适配器分别挂载独立节点，实际调用正式 `renderScoreNoticeBlob` 导出 PNG。模板通过字段绑定填入标题、日期、姓名、成绩与评语。
- 通用画布实验：从真实原通知导出隐藏动态文字后的静态底板；姓名、日期、标题、科目、等级、等级描述、评语全部由变量文字层重新绘制。按 DOM 实测坐标、字号、颜色和对齐映射到现有毫米坐标图层，调用正式 `renderCardTemplate`，未修改画布渲染器。
- 静态底板只代表该三科目布局；其中装饰已经合成为底板，因此尚不能证明独立装饰图层编辑或科目数量自适应。这是对现有画布的首轮能力测试，不是最优排版调参结果。
- 用 Pillow/NumPy 比较未缩放原始 PNG 的 RGBA 像素，并逐张查看图片、检查正文是否超出导出边界。普通场景额外验证正式导出默认的 2 倍清晰度。

## 实测发现的缺口

1. **文字能力。** 当前画布固定使用无衬线字体；原通知标题使用宋体、姓名和评语使用手写字体、等级使用 Georgia。图层缺少字体选择、字距、可配置行距、描边、阴影、基线及单行/多行排版控制。原标题有 4px 字距与 0.5px 描边，无法用现有参数表达。
2. **结构化成绩区。** 三科目底板只能代表固定布局。科目卡片需要独立结构、图标、配色、等级/分数规则和不同科目数量的自适应，不能只在底图固定空白处写字。
3. **原通知的样式缺陷。** 子组件使用 `:global(.score-report--subjects-dense) .子元素` 等写法，当前编译产物丢失后续子选择器，将本应隐藏装饰的 `display: none` 应用到了整个通知。紧凑版也出现尺寸规则错位。8 科目根节点导出高度 1086px，但正文滚动高度 1308px，评语底边达 1254px，实际 PNG 被裁切。应修复选择器后重新确定完整基准图，不能冻结这些缺陷作为标准。

## 后续硬性验收

- 原通知素材进入可编辑模板，装饰与动态内容分离；变量保持可替换，模板不保存真实学生信息。
- 补齐字体、字距、行距、描边、阴影、文本换行和结构化成绩/评语内容块，再用同一批数据对照。
- 原通知内置模板的正常场景保持零像素差异；通用模板复刻在相同浏览器、字体、尺寸和导出倍率下也以零像素差异为目标，任何差异应定位原因，不以整体相似度代替验收。
- 原本有缺陷的紧凑/密集布局先修复完整性，再建立新基准；所有图片必须有有效尺寸，评语完整，不能通过两张同样被裁切或空白的图片获得“通过”。
- 验证原始尺寸和默认 2 倍清晰度，分别改变姓名、标题、日期、科目数、分数/等级、空值及长评语；另验收上传独立素材、编辑图层、保存/重开和批量导出。

## 本次实现后的验收

实际调用 `captureNoticeTemplate` 把原通知转为纯数据的素材树，再使用正式 `renderCardTemplate` 的通用素材分支独立渲染。素材引用、动态变量和图层均保存为模板数据；未使用已填写学生信息的整张背景，渲染时不依赖原通知 Vue 组件。

| 3 科目等级 | 1448×1086 | 0 | 评语完整 |
| 5 科目分数，含真实 0 分 | 1448×1086 | 0 | 0 分保留，装饰边缘一致 |

紧凑/密集原通知先修复 Vue 全局选择器，避免子元素隐藏规则作用于根节点。通用模板直接序列化已内嵌的样式和字体，避免二次读取计算样式引入装饰边缘取整差异。

正式产品流程使用独立浏览器资料和虚构 60 人班级验证：相关五个页面在三种 PC 窗口下预览可滚动到底部，无窗口横向溢出，操作栏位于主内容底部之内；所有预览滚动容器均由 `el-scrollbar` 提供并隐藏原生滚动条。还实际下载原通知 PNG/PDF/ZIP，转换模板保存到 IndexedDB、读取后自动选用三人通知名单，并逐人输出 PNG/ZIP/PDF。保存的素材模板包含 52 个图层、20 个去重素材，不包含测试学生姓名。

证据补充位于忽略目录 `output/playwright/`：`workbench-check.log`、`material-ui.log`、`reopen-material-ui.log` 与实际下载文件；像素比较见 `notice-material-proof/scene-pixel-comparison.json`、`images/fixed-*-{original,scene}.png` 和 `images/double-{original,scene}.png`。

转换模板保持创建时的科目数量和分组结构，科目数变化后需重新转换；原通知仍自动排版。当前逐像素结论限定于本机 Chrome、默认字体和同一运行环境；用户上传字体及跨系统渲染尚未单独进行逐像素验收。

正式页面另做了同一学生的原通知与重开模板 2 倍 PNG 对比：2896×2172，482 个像素有差异，最大单通道差值仅为 1/255，均集中于三颗 15px 星形装饰的半透明边缘。没有位置、尺寸、文字或内容变化；独立实验的六组与 2 倍对照仍为零差异。这里单独记录正式页面的透明边缘舍入，避免把实验结论夸大为所有环境逐像素一致。

最终交互补充：1280×600 与 1093×614 逻辑视口（后者对应约 1366×768 在 125% 缩放下的可用尺寸）也通过布局检查；最小预览高度为 293px，操作栏未超出窗口。通知导出停止后实际 ZIP 保留 2/3 名学生；当前图片与批量导出均使用原尺寸离屏节点。替换校徽素材后成功保存；图层拖动在缩放预览下按实际毫米比例换算通过。PDF 实际文件检查均为三页，通知使用 A4 横向，素材模板保持自身纸张尺寸。
