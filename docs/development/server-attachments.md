# 服务器素材库与附件存储

## 归属与入口

“班级与学生”中的“账号共用素材”页签提供素材库；还没有班级时也可在该页直接使用。素材按账号归属，不随班级或学期切换。管理员代管操作沿用顶部目标账号，读写审计始终记录真实操作者和数据归属。

现已完成上传、分页列表、按需预览、下载、重命名、相邻排序及软删除，并接入裁剪/旋转和试卷排版草稿。布局保存不可变图片版本快照；原图后续修改不会改写已保存的版式。排序通过上下移动操作完成。错题本已移除，不作为附件调用方。

## 文件与数据库

schema v6 新增 `attachments` 元数据表和 `attachment_blobs` 占用记录。数据库不保存图片 Blob/Base64。默认文件目录为 `DATABASE_PATH` 所在目录下的 `attachments`，可通过 `ATTACHMENT_DIR` 指定；两者都属于运行数据，不提交到 Git。

文件路径由服务端账号 UUID 和 SHA-256 摘要组成，不使用客户端文件名。不可变文件先写同目录临时文件，再原子改名；替换内容时生成新的摘要文件，保留原文件。元数据、幂等回执及审计在同一短事务内提交。文件系统与 SQLite 不能组成一个真正的原子事务：进程异常可能留下未被数据库引用的文件，但不会将半写文件当作正式图片；本阶段不自动删除这些文件。

上传者只能选择素材名称，不能上传 owner、磁盘路径或权限字段。公开 DTO 不包含目录、磁盘路径或摘要。目录不能配置为公开静态资源，下载全部通过鉴权接口。

## 当前限制

- 格式：PNG/JPEG；SVG、其他格式和 MIME 与实际文件头不符的上传拒绝。
- 单张：最大 8 MB；宽高各不超过 10000，像素总数不超过 2000 万。
- 每批：前端最多 10 张，顺序上传；失败时保留剩余文件、素材 ID 和幂等键，重试不重复创建成功项。
- 账号累计占用：512 MB，同账号相同摘要只计一次。旧版本和软删除文件仍计入占用，不能靠反复删除绕过配额。
- 列表：每页 50 条，只传元数据，预览时才下载单张图片。

服务端做文件头、PNG 块边界/结尾、JPEG 尺寸头及尺寸检查，不是完整图片解码器，也没有病毒扫描。客户端展示依赖浏览器图片解码。文件下载校验 SHA-256，文件丢失或损坏返回明确错误；运维应按下面的一致备份恢复。

## 版本、权限与删除

上传新文件要求版本 0；更换内容、重命名和删除均检查当前版本，旧版本返回 409。请求的内容摘要、名称及版本参与幂等校验，响应丢失时可以使用原键重试。软删除保留元数据和文件，普通列表与下载不再返回已删除项；没有回收站恢复或自动清理接口。

二进制传输使用原始文件，避免 Base64 体积膨胀。预览/下载文件时指定素材版本；文件传输结束后再读取少量元数据，重新检查代管资格、删除和版本变化，然后才创建预览 URL 或下载文件。账号切换及组件销毁会取消请求、清空待上传队列、释放 Blob URL，旧响应不能回填新账号。收到 401/403 时清理已展示的图片及列表。

响应使用 `Cache-Control: no-store`、`X-Content-Type-Options: nosniff`、限制性 CSP 和附件下载文件名，不提供永久公开 URL。

## API

路径前缀 `/api/v1`，所有接口使用原有 Bearer Token；代管范围由 `X-Managed-Account-Id` 指定。

| 方法   | 路径                                 | 输入                                                                               |
| ------ | ------------------------------------ | ---------------------------------------------------------------------------------- |
| GET    | `/attachments?offset=0`              | 每页 50 条元数据                                                                   |
| GET    | `/attachments/:id`                   | 读取元数据，重新校验权限                                                           |
| PUT    | `/attachments/:id`                   | PNG/JPEG 二进制；X-File-Name 为 encodeURIComponent 名称，X-Expected-Version 为版本 |
| PATCH  | `/attachments/:id`                   | `{ version, name }`                                                                |
| DELETE | `/attachments/:id`                   | `{ version }`                                                                      |
| GET    | `/attachments/:id/content?version=1` | 读取指定当前版本内容                                                               |

写请求都要求 `Idempotency-Key`。未登录上传在读取图片请求体前拒绝；其他 JSON 业务接口仍保持 1 MB 请求体上限。后端提供内容替换接口，前端裁剪/旋转将在后续接入。

## 一致备份与恢复

必须同时保存 SQLite 和完整附件目录；只备份数据库不能恢复图片，只备份目录不能恢复归属及版本。建议运维步骤：

1. 暂停后端服务及所有写入进程，让数据库和文件目录保持不变。
2. 使用 Python 标准库 `sqlite3.Connection.backup()` 将当前数据库备份到新的时间戳目录；它会读取已提交的 WAL 内容，避免直接复制运行中的主库而遗漏记录。
3. 将整个 `ATTACHMENT_DIR` 复制到同一个备份目录，包括已软删除、旧版本和所有账号子目录；保留目录结构和权限。
4. 在隔离目录检查备份库 `PRAGMA integrity_check`、外键，并根据 `attachment_blobs` 的账号/摘要逐项检查文件大小和 SHA-256，再恢复后端服务。

恢复同样先停止所有写入：保留当前库和文件作回退副本，将已验证的备份库与附件目录成对恢复，使用正确的 `DATABASE_PATH`、`ATTACHMENT_DIR`，再检查 schema 和文件完整性后启动。不要把不同时点的数据库与附件目录拼在一起，也不要只替换主库而留下原库的 WAL/SHM。跨版本备份要使用对应程序版本先恢复验收，再执行增量迁移。已提供离线自动备份、校验和恢复工具，见 [运维说明](./server-operations.md)；临时目录恢复测试已覆盖，真实环境灾备演练仍需单独执行。

## 实现与本轮验证

共享类型在 `packages/shared/src/Attachments.d.ts`；文件处理、元数据服务、路由分为三个小文件。前端将二进制能力纳入统一 API 客户端，素材状态和界面分别放在 `useApiAttachments.ts`、`AttachmentPanel.vue`，不读取旧 Dexie 素材。

测试使用内存 SQLite、Fastify inject、操作系统临时目录和模拟前端请求，不监听端口，也不操作真实素材目录。定向验证权限隔离、代管撤权、版本、幂等、软删除文件保留、配额、无效图片、文件丢失，以及二进制传输、失败重试、晚响应和 URL 清理。前后端必要类型检查和改动文件 Lint；全量回归与前端完整构建仍留到改造收尾。
