# 教师排课工具第一阶段说明

## 目录说明

当前排课功能已独立收拢到 `src/views/tools/teacher-schedule/` 下：

- `TeacherSchedulePage.vue`：排课工作台页面
- `constants.ts`：阶段性配置、选项和默认状态
- `README.md`：当前阶段的思路说明

相关状态和数据结构仍复用现有的 `stores/teacher-schedule.ts` 和 `types/TeacherSchedule.ts`，后续再按阶段继续拆分。

## 目标

第一阶段先把排课工具落成一个可用的工作台，不追求完整的自动排课优化，优先完成下面四件事：

1. 录入班级、课程、教师和约束
2. 录入去年和上学期的任教历史
3. 基于历史和规则生成排课草案
4. 支持人工查看、重算、删改和回退

## 设计原则

### 1. 排课以班级为主轴

学校先确定班级，再围绕班级配置课程和教师。  
课程模板不是写死的，而是按学期、年级动态配置。

### 2. 课程是动态字典

课程名称、分类、是否主课、是否可跨班、是否可跨年级，都可以在页面里配置。  
后续新增“劳动”“阅读”“校本课”等，不需要改代码结构。

### 3. 教师画像和约束分开维护

教师基础信息只描述能力边界，例如：

- 可教课程
- 是否班主任候选
- 是否可任主课
- 是否可跨班、跨年级
- 最大周课时

特殊限制通过“约束”单独维护，例如：

- 不能任主课
- 不能任班主任
- 不能跨班
- 不能跨年级

### 4. 历史优先，最小扰动

年度沿用优先于学期沿用。  
去年带过的老师、上学期带过的老师，会优先被推荐到当前方案中。

### 5. AI 只做辅助

AI 负责：

- 解释规则
- 给出推荐教师
- 输出方案摘要

AI 不作为最终裁判。最终结果仍然需要人工确认和微调。

## 第一阶段页面

当前工作台分为 7 个区域：

1. 学年学期
2. 班级
3. 课程
4. 教师
5. 约束
6. 历史
7. 方案

## 数据结构

### 学年学期

记录当前排课周期，包含：

- 学年
- 学期
- 起止日期
- 状态

### 班级

记录班级名称、年级、班号、人数和班主任。

### 课程

记录课程字典，支持动态增删改停用。

### 年级课程模板

定义某个年级在当前学期需要开哪些课、每周几节。

### 教师

记录教师画像和排课能力边界。

### 约束

记录教师级别的特殊限制，硬约束会直接参与草案生成。

### 历史

记录去年或上学期的任教情况，用于继承优先。

### 方案

保存草案版本、分配结果和冲突信息。

## 草案生成规则

当前版本采用简单规则：

1. 先分配班主任
2. 再按年级模板分配课程
3. 优先使用历史中出现过的教师
4. 如果候选教师不足，就记录冲突
5. 如果教师课时超限，就记录冲突
